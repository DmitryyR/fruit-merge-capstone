## Функціональні критерії

Наведені правила взято з посібника. Позначені уточнення — пропозиції агента, що потребують погодження разом із планом.

| ID | Вимога та точне очікування | Перевірка | Етап |
|---|---|---|---|
| FR-01 | 30 записів, рівні 1–30 без пропусків, унікальні ID, непорожні назви, власне доступне зображення, додатний скінченний радіус | `catalog.test.ts`, завантаження всіх textures у браузері та asset register | T1, T4 |
| FR-02 | Миша/дотик задає drop X у межах `[left+radius, right-radius]`; один жест — одне скидання | `drop-controller.test.ts`, реальні mouse/touch E2E | T2 |
| FR-03 | Пара живих різних ID рівня n<30 дає один n+1; різні рівні й (30,30) не зливаються | `merge.test.ts`, `merge-coordinator.test.ts`, реальне зіткнення Matter | T1, T2 |
| FR-04 | За пару n додається `10*n` один раз; повторний callback не змінює результат | (1,1) → рівень 2, +10; (2,2) → рівень 3, +20; повтор пари → +0 | T1, T2 |
| FR-05 | Current/next генеруються лише з 1–5. Після успішного drop next стає current, генерується один новий next | Детермінований RNG у unit-тестах; заблокований drop не зсуває чергу | T2 |
| FR-06 | У playing фрукт віком >1000 мс, з topY<dangerLineY та швидкістю <25 px/s безперервно перебуває в небезпеці 2000 мс → gameOver; далі drop/merge заблоковані | `danger.test.ts`: 1999/2000 мс; age 1000/1001; speed 24.9/25; `session.test.ts`, E2E | T3 |
| FR-07 | Пауза заморожує фізику, очки, вік і danger timer; resume продовжує їх; restart очищує поле, очки, черги й таймери та повертає playing | Unit; E2E pause/resume; 10 restart поспіль | T3 |
| FR-08 | Рекорд зберігається між reload; менший score і restart його не зменшують | `high-score.test.ts`, E2E із перезавантаженням | T3 |
| FR-09 | Керування й HUD працюють при 390×844 та 1440×900; після resize координати залишаються правильними | Обидва viewport в E2E; ручна миша й реальний телефон, якщо доступний | T2, T4 |

Уточнення FR-06: y спрямований вниз; рівність topY=dangerLineY не вважаємо перетином. Таймер окремий на кожний ID, скидається при порушенні будь-якої умови та видаляється для відсутнього/merged фрукту. Пауза нічого не скидає. Вік і тривалість рахуються часом симуляції; на кроці, що перетинає grace period, до небезпеки зараховується лише час після 1000 мс. Від'ємний/нескінченний delta відхиляється. Після gameOver стан не відновлюється без restart.

Уточнення FR-02/05: drop по pointer-up на полі, лише primary pointer; відпускання поза полем скасовує жест. Cooldown 300 мс часу симуляції. Блокування на паузі, gameOver і під час cooldown не змінює чергу. Це запропоновані параметри, а не вимоги курсу.

## Межі та ризик 30 рівнів

Немає серверу, реєстрації, платежів, реклами, онлайн-рейтингу, магазинів застосунків і збереження незавершеної партії. Публічний deploy корисний, але локальний запуск з README достатній для базового продукту.

30 рівнів — каталог і коректні переходи, не обіцянка досягнення останнього рівня у короткій партії. Якщо drop обмежений 1–5, для одного рівня 30 навіть із самих п'ятих потрібні `2^(30-5) = 33 554 432` початкові фрукти. Тому високі рівні перевіряємо синтетичними сценами й так їх називаємо у відео. Зменшення каталогу або зміна прогресії можливі лише окремим рішенням користувача; до цього зберігаємо посібник.
